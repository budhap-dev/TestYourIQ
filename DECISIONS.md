# Decisions

Choices made where the build prompt left something **Open**, or where I had to pick a default.
Each entry says what was chosen and why. Change any of them freely.

## Step 2 — Pattern-matrix engine

| Topic                  | Choice                                                                                                                                                                                                                                                                      | Why                                                                                                                                                                                                                                                                                      |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Wrong answers          | **Balanced option set** (deliberate change from §4.3). Starting from the answer, 2 or 3 attributes are each given one plausible wrong value, and every combination becomes an option (4 or 8). Wrong options break 1–3 rules.                                               | Chosen by owner. With "exactly one rule broken", the answer is always the option most like the others and can be found without solving the grid. In a balanced set every value of every varied attribute appears in exactly half the options, so the options alone give no clue. Tested. |
| Wrong values           | Level 1–2: values seen elsewhere in the grid. Level 3–5: one step from the right value (e.g. count ±1, 45°/90° turn).                                                                                                                                                       | Plausible mistakes, not noise.                                                                                                                                                                                                                                                           |
| Difficulty levels      | 1: one progression, 4 options · 2: two rules (progression/row-constant), 4 options · 3: two rules incl. a distribute, 4 options · 4: three rules, 8 options · 5: four rules incl. two distribute, 8 options. Levels 3–5 never let the answer be copied from a visible cell. | Explicit parameters per §4.3, in `MATRIX_LEVELS`. Options are capped so that from level 2 up, only attributes that really vary in the grid are varied among the options.                                                                                                                 |
| Seed IRT parameters    | b = −2, −1, 0, +1, +2 and a = 1.0–1.3 for levels 1–5                                                                                                                                                                                                                        | Starting values only; recalibrated from real responses later (§6.3).                                                                                                                                                                                                                     |
| Ambiguity              | Every item is checked against a solver that reads rows **and** columns for constant, progression and distribute patterns; items where any attribute has a second reading are regenerated. Tests use a separate checker.                                                     | Guarantees exactly one defensible answer.                                                                                                                                                                                                                                                |
| Shading                | Outline / half-tone / solid instead of stripes                                                                                                                                                                                                                              | Hatching became unreadable for small shapes in option tiles.                                                                                                                                                                                                                             |
| Rotation               | Only arrows and triangles rotate, and only when rotation is a rule; shape is then fixed. Rotation rules are allowed from level 1.                                                                                                                                           | Rotation is invisible on symmetric shapes; duplicate-looking options are rejected. Owner agreed to let calibration show whether level-1 rotation items are too hard rather than exclude them now.                                                                                        |
| Item keys              | `gen:<generator>:v<version>:d<difficulty>:<seed>`; bank items `bank:<id>`                                                                                                                                                                                                   | Version in the key means changing a generator never silently changes old items.                                                                                                                                                                                                          |
| Answer checking        | Server regenerates the item from its key and compares                                                                                                                                                                                                                       | No answer storage needed.                                                                                                                                                                                                                                                                |
| Keeping answers secret | Clients get `toPublicItem` (area, content, option count) only, never the key or seed. ESLint blocks UI code from importing generators; the production bundle is checked for generator code.                                                                                 | §5.5. **Note for step 5:** the repo is public, so anyone with a seed could regenerate the answer. Item tokens must therefore be encrypted (or an opaque reference), not just signed.                                                                                                     |
| Screen readers         | Matrix cells and options have text descriptions (e.g. "3 large shaded crosses"); the landing page says pattern questions work with a screen reader and shape-turning (spatial) ones don't                                                                                   | Confirmed by owner. Gives blind users access to pattern items, though for them the item becomes partly verbal.                                                                                                                                                                           |
| Dev workbench          | `/dev/puzzles`, dev server only, stripped from production builds                                                                                                                                                                                                            | Inspect any seed and level, show rules and answer.                                                                                                                                                                                                                                       |
| Script runner          | `tsx`                                                                                                                                                                                                                                                                       | Runs TypeScript scripts with the same module resolution as the app.                                                                                                                                                                                                                      |

## Step 3 — Numerical, spatial and verbal items

| Topic                  | Choice                                                                                                                                                                                                                                                                                                                                                     | Why                                                                                                                                                                                                                                                                                                  |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Number series          | 6 terms shown, find the 7th. Level 1: +n · 2: −n, ×n · 3: growing gaps, two interleaved sequences · 4: add-the-previous-two, alternating +/×, square numbers ± c · 5: doubling gaps, ×2 ± c. Whole numbers 1–999.                                                                                                                                          | Explicit families per level (`SERIES_LEVELS`).                                                                                                                                                                                                                                                       |
| Number analogies       | Three worked examples (x → y), then a query. Level 1: x + c · 2: c·x · 3: c·x ± d, x² · 4: x² ± c, x(x + 1) · 5: x³, x² + c·x.                                                                                                                                                                                                                             | Three examples pin down two-parameter rules (`NUMBER_ANALOGY_LEVELS`).                                                                                                                                                                                                                               |
| Number options         | **Evenly spaced** (e.g. 50 / 60 / **70** / 80), with the answer's position drawn uniformly and once per item. Spacing is a likely mistake for that rule (one step too many or too few, or e.g. q² for cubes), then generic slips (off by 10, 5, …). If the answer is a multiple of 5 or 10, every option is too. 4 options at levels 1–3, 6 at levels 4–5. | Interprets "each wrong answer breaks one rule" for numbers. Wrong values defined relative to the answer let "pick the one closest to the others" beat chance (39% vs 25% in testing). Tests now hold middle, nearest-neighbour and closest-to-mean guessing at chance, and roundness at or below it. |
| Number ambiguity       | A solver checks polynomial (up to third differences), ×r + c, add-the-previous-two, interleaved, alternating-operation and geometric-gap readings for series, and linear, x² + c, x² + cx, cx² and x³ + c for analogies. Items with a second answer are regenerated. Tests use a separate checker.                                                         | Exactly one defensible answer.                                                                                                                                                                                                                                                                       |
| Spatial items          | Shapes of 5–8 squares. "Rotate": find the same shape turned. "Mirror": find its mirror image (a mirror line is drawn). Options are every combination of mirrored/not and 1–2 moved squares (4 or 8 options), so each option has exactly one mirror partner and none is the odd one out. Quarter turns only.                                                | Same balanced idea as the matrices.                                                                                                                                                                                                                                                                  |
| Spatial levels         | 1: 5 squares, 4 options · 2: 6 squares · 3: 6 squares, subtle moves, mirror options turned · 4: 7 squares, 8 options · 5: 8 squares, 8 options. The answer never looks identical to the target.                                                                                                                                                            | `SPATIAL_LEVELS`.                                                                                                                                                                                                                                                                                    |
| Verbal bank            | 182 adult items (106 analogies, 76 odd-one-out) and 94 junior items (54 + 40), British English, in `src/engine/verbal/bank.*.json`, validated with zod on load. Option order is shuffled deterministically from the item id. Seed IRT b = difficulty − 3, a = 1.                                                                                           | Written for this app. Difficulty is my estimate, to be recalibrated. **Worth a review by you or another reader for wording and fairness.**                                                                                                                                                           |
| Client/server boundary | ESLint allows UI code to import only `engine/types`, `engine/svg`, `engine/*/model` and `engine/*/render`.                                                                                                                                                                                                                                                 | Generators, solvers and the verbal bank (answers) can't reach the browser bundle.                                                                                                                                                                                                                    |
| Item display           | One `ItemView` for all kinds. Picture options in a 2×2 or 4×2 grid, number options in 2×2 or 3×2, word options in a row on wide screens and 2 columns on phones.                                                                                                                                                                                           | Spec §3: 2×N / 3×N reflow, 44px+ targets.                                                                                                                                                                                                                                                            |

## Step 4 — Scoring

| Topic      | Choice                                                                                                                                                                                                    | Why                                                                                                                                                                                                                                 |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Model      | 2PL logistic, P = 1 / (1 + e^(−a(θ − b))), no 1.7 scaling constant                                                                                                                                        | Seed a/b values are set on this scale; calibration re-estimates them on the same scale.                                                                                                                                             |
| EAP        | Quadrature on a grid from −5 to +5 in steps of 0.02, computed in log space so long tests can't underflow. SE = posterior SD.                                                                              | Accurate to better than 0.001 against direct integration (tested).                                                                                                                                                                  |
| Prior      | Standard normal **on the age band's own scale**, N(band mean, band SD), rather than N(0, 1)                                                                                                               | N(0, 1) is centred on young adults and would pull every junior's estimate upward (about +3 IQ points for an average 8-year-old). This is the spec's "standard normal prior", measured in the test-taker's own reference population. |
| Age bands  | Junior 8–15 (one-year bands), adult 16–19, 20–24, 25–34, 35–44, 45–54, 55–64, 65–74, 75+. Ages 8–110 accepted.                                                                                            | §6.2.                                                                                                                                                                                                                               |
| Seed norms | SD 1 everywhere. Mean θ: age 8 −2.0, rising to age 15 −0.25; adults 16–19 −0.1, 20–34 0, then 35–44 −0.05, 45–54 −0.15, 55–64 −0.3, 65–74 −0.5, 75+ −0.75. All have n = 0, so results show "Calibrating". | Clearly marked estimates (§6.3), shaped like typical developmental and ageing curves for fluid reasoning. Replaced by `npm run calibrate`.                                                                                          |
| IQ display | Rounded, clamped to 55–145; "145+" / "below 55" beyond. 95% range clamped the same way. Percentile labels: "more than 99%" / "less than 1%" at the extremes.                                              | §6.2.                                                                                                                                                                                                                               |
| Area bands | EAP on each area's items, banded at z = ±0.67 (roughly bottom quarter / middle half / top quarter)                                                                                                        | §6.1: broad bands, because each rests on few items.                                                                                                                                                                                 |

## Step 5 — Database and API

| Topic                      | Choice                                                                                                                                                                                                                                                                                                                                                               | Why                                                                                                                                                      |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Layout                     | Logic in `/server` (service, handlers, stores, tokens); `/api/**` files are one-line Web-standard (`GET`/`POST`) wrappers                                                                                                                                                                                                                                            | Logic is unit-testable without Vercel, and the same handlers serve local dev.                                                                            |
| Local dev                  | A Vite plugin serves `/api/*` from `server/handlers.ts` in `npm run dev`. If `DATABASE_URL` is empty, it falls back to an in-memory store (dev only; production refuses to start without a database).                                                                                                                                                                | §2: runs fully locally, with or without Postgres.                                                                                                        |
| Drivers                    | Neon URLs use `@neondatabase/serverless` `Pool`; other URLs (local Postgres) use `pg`                                                                                                                                                                                                                                                                                | Same pg-compatible API; transactions with `select … for update`.                                                                                         |
| ESM on Vercel              | Server and engine imports use `.js` extensions and JSON import attributes; `npm run check:api` compiles like Vercel and imports every function under plain Node                                                                                                                                                                                                      | Vercel compiles functions file by file. Extensionless ESM imports fail there at runtime, not at build time.                                              |
| Test structure (blueprint) | 4 sections (pattern, numerical, spatial, verbal) × 8 items. Adult time limits 10 / 7 / 6 / 4 min (27 min); junior 11 / 8 / 7 / 5 min (31 min). Item types alternate within a section (series/analogy, rotation/mirror, verbal analogy/odd-one-out).                                                                                                                  | Same structure for everyone: parallel forms (§5.3). Section timers per §3.                                                                               |
| Adaptive selection         | Fixed opening difficulties (adult 2 then 3; junior 1 then 2), then the difficulty (or bank item) with maximum Fisher information at the current EAP estimate. Adult 1–5, junior 1–4, at most 3 items of one difficulty per section. Ties are broken by a seeded shuffle.                                                                                             | §5.4 within blueprint constraints, so forms keep a comparable spread.                                                                                    |
| Item seeds                 | Derived on the server from a random per-attempt `form_seed` and the item position, never from client input. Any clash with a seen item moves to the next seed.                                                                                                                                                                                                       | §5.5.                                                                                                                                                    |
| Seen items                 | Recorded when an item is **shown**, not when answered. Verbal bank items exclude everything seen. If a bank runs out (juniors after about 11 tests), the verbal section gets shorter rather than repeating items.                                                                                                                                                    | §5.1, never repeat. Exhaustion is tested.                                                                                                                |
| Item tokens                | AES-256-GCM, keyed by HKDF from `SESSION_SECRET`, with attempt, position, item key and expiry. Must match the attempt's pending item, so a replayed or reordered answer gets 409.                                                                                                                                                                                    | §8. Encrypted rather than signed, because the public repo would let a readable seed reveal the answer.                                                   |
| Test-taker id              | Random UUID, as an HTTP-only `SameSite=Lax` cookie (`Secure` in production, 400 days) plus the same signed token in localStorage, sent as `x-taker`                                                                                                                                                                                                                  | §5.2. Signed so it can't be forged; the localStorage copy survives cookie clearing.                                                                      |
| Timing                     | Each section has a server-side deadline plus 10 s grace. When it passes, or the client reports time up, the current item is timed out and the section's remaining slots are filled with the items the test would have chosen, all scored incorrect and marked `presented = false` (not added to seen items). Reported response times are capped by the server clock. | §6.1: timed-out items count as incorrect.                                                                                                                |
| Resume                     | Extra endpoint `GET /api/attempts/:id` re-issues the current item after a reload                                                                                                                                                                                                                                                                                     | Otherwise a reload would lose the test.                                                                                                                  |
| Abandonment                | Starting a new attempt abandons any in-progress one; attempts older than 3 hours are abandoned when touched                                                                                                                                                                                                                                                          | Keeps state simple; abandoned attempts never enter norms.                                                                                                |
| Norm eligibility           | Consent, **and** the taker's first attempt of any kind (`attempt_number = 1`), **and** no quality flag. Flags: median response under 3 s, ≥ 75% of answers in one position, or person-fit lz < −2.5.                                                                                                                                                                 | §5.6. Because the first item is shown as soon as an attempt starts, even an abandoned attempt means items were seen, so later attempts are excluded too. |
| Rate limit                 | 5 attempts per test-taker per rolling hour (429)                                                                                                                                                                                                                                                                                                                     | §8. No IP-based limit, since IPs aren't stored.                                                                                                          |
| Access                     | Attempts and results are visible only to the test-taker who owns them. Unknown and foreign attempt ids both return 404.                                                                                                                                                                                                                                              | Privacy. Result links aren't shareable.                                                                                                                  |
| Seed IRT parameters        | `npm run seed` writes version 1 for every template (`gen:<id>:v<n>:d<1–5>`) and bank item. Lookups use the newest version, falling back to engine values.                                                                                                                                                                                                            | §4.4, §6.3.                                                                                                                                              |
| Postgres testing           | The real migrations and store run against PGlite (embedded Postgres, dev dependency) in the test suite                                                                                                                                                                                                                                                               | Verifies the SQL without a database server.                                                                                                              |
| Retention                  | Not automated yet; 24 months is stated on the privacy page                                                                                                                                                                                                                                                                                                           | **Open:** a purge script or Neon scheduled job before launch.                                                                                            |

## Step 6 — Test and results screens

| Topic              | Choice                                                                                                                                                                                                                                                                                                           | Why                                                                                                                                                  |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| Setup              | Three steps on one page: About you (age, or a date of birth turned into whole years in the browser and never sent; optional consent), Practice (2 untimed questions with feedback), Ready (sections, timings, keys). Retake notice from `GET /api/me`.                                                           | §3 flow. Consent is **off by default for everyone**: UK GDPR doesn't allow pre-ticked consent, and the ICO Children's Code needs it off for juniors. |
| Practice questions | Two hand-written, static items (a matrix and a series), with answers in the client                                                                                                                                                                                                                               | They're demonstrations, never part of a test, so no secret is exposed.                                                                               |
| Section breaks     | No separate break screen. The first question of a section shows a short banner ("Numbers: 8 questions, 7 minutes").                                                                                                                                                                                              | The server starts a section's clock when the previous one ends. A break screen would silently eat into it.                                           |
| Timer              | `m:ss` in muted text, turning accent-coloured (not red, never flashing) in the last minute, with a single polite screen-reader announcement. Uses the server's clock offset. When it reaches zero, the client reports a timeout and moves on.                                                                    | §3: visible but not stressful.                                                                                                                       |
| Controls           | Keys 1–8 choose and Enter confirms; Skip and Confirm buttons; no back button (the server only serves the current question)                                                                                                                                                                                       | §3 accessibility and no going back.                                                                                                                  |
| Reload             | The test page resumes from the server; the results page finishes the attempt if needed, or returns to the test                                                                                                                                                                                                   | Reload-safe throughout.                                                                                                                              |
| Results            | Big IQ number (or "145+" / "below 55"), "likely between X and Y", a percentile sentence for the age band, the calibrating note while n < 500, a retake note with the previous score and a practice-effect caveat, a bell curve with the estimate and shaded range, and area bands on a below/average/above track | §3, §6. Area results show position and band only, not numbers.                                                                                       |
| Bell curve         | Neutral population curve, estimate and range in the accent colour, three to five tick labels. Drawn at the container's real width, so text stays legible on phones. The text summary doubles as the accessible description.                                                                                      | Chart guidance: one highlighted mark, recessive axes, text in text colours, readable at 360px.                                                       |
| Wire types         | `src/shared/api.ts`, used by both server and browser. UI may type-import from the engine (erased at build).                                                                                                                                                                                                      | One source of truth for the API shape.                                                                                                               |

## Step 7 — Retakes

| Topic                 | Choice                                                                                                                                                                                                                     | Why                                                                                                                                                                                                         |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| What counts as "seen" | Both the item key (generator + seed, or bank id) **and** a content fingerprint of the question (ignoring option order; for odd-one-out items, the set of words). Selection skips a seed whose key or puzzle has been seen. | Different seeds can produce the same easy puzzle (level-1 series have a few hundred variants), and the spec's "never repeat" means what the person sees. Tested over 20 retakes: 640 questions, no repeats. |
| Exhaustion            | After 200 seed clashes for one slot, the last candidate is used. Verbal sections shorten instead of repeating.                                                                                                             | Practically unreachable for generated items, and keeps the test from stalling.                                                                                                                              |
| Resume                | `GET /api/me` reports an unfinished attempt (younger than 3 hours); setup offers "Resume my test" and warns that starting anew ends it                                                                                     | People who close a tab can carry on instead of losing the attempt and burning items.                                                                                                                        |
| Retake messaging      | Setup says they've taken it before, that questions will be new, and that familiarity can still lift scores. Results show the previous score and range with the same caveat. Retakes never enter norms.                     | §3.5, §5.6, §5.7.                                                                                                                                                                                           |
